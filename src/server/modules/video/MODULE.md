# Module: video

**Purpose:** Build scene previews and project renders from project-owned scenes, voiceovers, SFX, and BGM.
**Owns collection(s):** none in this phase; `project` owns scene/project references and `file-store` owns binary metadata.
**May import (via public `index.ts` APIs):** project, asset, job, shared file-store, TTS, and Freesound adapters.
**Public API:** renderer interfaces/factory and orchestration functions exported from `index.ts`.

## Invariants

- Popup analysis selects the shared Claude CLI model default `claude-sonnet-5-5` when `cliModel` is omitted and passes medium effort for every chunk/retry. Per-call logs include the resolved model and effort; API analysis still uses the project's selected provider/model.

- Video code never calls `getCollection('projects')`; scene/project writes stay in the project service.
- Every FFmpeg input path is resolved through file-store ownership checks for the current project.
- Scene segments always have H.264 video plus stereo 48 kHz AAC audio, including generated silence when voiceover or SFX is absent.
- SFX is normalized to the voiceover reference at render time, then uses project `sfxVolume` (default `0.5`, about -6 dB); BGM remains at `0.1` (-20 dB). SFX is never looped.
- The Remotion composition is isolated under `src/remotion`; the server renderer resolves only project-owned media, stages generated names under the bundle-output `public/renders/<renderId>/`, and cleans that directory after each render. An optional project logo is resolved with purpose `logo`, staged as `logo.<ext>`, and rendered once at composition level at 25% opacity outside FilmLook. FFmpeg intentionally ignores it.

## Rendering flow

`FfmpegRenderer` creates a temporary segment for each scene, scales/pads the visual to the project render settings, mixes voiceover and optional SFX, and concatenates segments in scene order. When BGM exists, a second FFmpeg pass loops/trims the BGM and mixes it with the concatenated audio.

The BGM pass intentionally runs a second FFmpeg pass over the full video: it copies the video stream and re-encodes the mixed audio. This is a deliberate simplicity/performance trade-off for this phase; long projects may benefit from a future single-pass filter graph.

`buildSceneArguments`, `buildConcatArguments`, and `buildBgmArguments` are pure argument builders so filter graphs can be tested without an installed binary. The renderer uses raw `child_process.spawn` argument arrays, streams stdout lines to `appendLog`, preserves stderr on failure, and removes temporary files in `finally` blocks.

The scene graph scales/pads visuals, adds first-frame padding at the start of measured short video assets, and trims the result to the scene duration. Before either renderer mixes SFX, it measures and normalizes a render-time copy to the mastered voiceover reference (-16 LUFS integrated, -1.5 dBTP ceiling); clips under 3 seconds use ebur128 measured gain plus a true-peak limiter, and longer clips use measured two-pass loudnorm. The stored Freesound file is never modified. Project `sfxVolume` (0–1, default 0.5) is applied after normalization in both engines. FFmpeg's scene `amix` uses `normalize=0` so adding SFX does not reduce the voice input. This requires FFmpeg 4.4 or newer; the locally installed 2026 build exposes the `amix.normalize` option. Remotion uses the keyframe when present or holds the clip's frame 0 before starting the clip at its own frame 0; embedded source-video audio is muted so it cannot bypass the explicit voice/SFX mix. Voiceover, SFX, and keyword overlays remain anchored to scene time 0 and do not move with the visual clip offset. The legacy `videoTailFileId` remains project/import data but is not staged or used by rendering. Cleanup failures are logged without replacing the primary render/staging error. Voiceover mastering uses the shared high-pass/loudness filter with an unmastered fallback; no silence trimming is applied. The mastered WAV is probed and its raw duration is stored per scene; `durationSec` is `round2(voiceoverDurationSec + sceneTailSec)`, with a default project tail of 0.2 seconds.

Fractional scene seconds are converted to whole frames with the shared `contracts/frame-math.ts` helper. Remotion places audio scene sequences back-to-back at those per-scene frame offsets; visual transitions may overlap, but do not shift audio starts or total composition frames. FFmpeg aligns each segment's duration to the same per-scene frame count, limits video with `-frames:v`, trims voice/SFX to the aligned scene duration, and `apad`s only to that bound. Concatenation adds no intentional inter-segment pause; remaining audible gaps include the stored WAV's own trailing/leading silence plus the configured tail. Real Rạch Gầm silence measurements remain unverified in the current environment.

`POST /api/project/:id/scenes/recompute-durations` probes already-stored voiceover files without calling TTS, leaves missing or failed probes untouched, and writes successful measurements/durations through a project-version and audio-file guarded batch mutation. It refuses to start while a render job is active. Existing `wordTimings` remain valid because the audio is unchanged; scene preview fingerprints already include `durationSec`, and Task 83's slow-down plan is recomputed from current scene duration at render time. Changing `sceneTailSec` affects future voiceovers and explicit recompute only; legacy projects read with the 0.2-second default. Studio's audio-only listener treats `voiceoverDurationSec` as the raw mastered-WAV duration: because Task 84 applies `sceneTailSec` with render-time `apad` rather than appending it to the WAV, known in-file tail is zero and the listener waits the full live draft tail. The existing duration mismatch helper remains the per-scene "Chưa áp dụng tail" indicator; missing measurements contribute no known in-file tail.

Bulk SFX generation returns per-scene outcomes and a batch summary in the job result/log. `POST /api/project/:id/scenes/generate-all-sfx` accepts `{ onlyMissing?: boolean }`; missing-only mode skips an existing project-owned, audio-purpose SFX file that is present on disk. Three consecutive scene-level persistent rate-limit outcomes end the batch early. The Studio's retry action sends `onlyMissing: true` after a batch reports failures. SFX provenance is retained in job logs/results rather than file metadata.

The orchestration services call VieNeu and Freesound adapters, store generated voiceover/SFX/BGM/render files through the configured file-store service, and mutate scene/project references only through the public project API. Freesound search query extraction maps known Vietnamese phrases, skips unknown non-ASCII phrases, preserves English Unicode letters, caps each scene at three ordered distinct queries, and ranks up to 15 results while excluding voice-like candidates. Voiceover batches run sequentially and continue after an individual failure; a failed scene keeps its previous reference and duration. A batch may start at a validated scene ID and checks cooperative cancellation between scenes without interrupting in-flight TTS.

The router is mounted explicitly at `/api/project`. Project-wide voiceover and render requests enqueue jobs; single-scene voiceover regeneration, SFX/BGM generation, and preview rendering remain synchronous. Worker handlers check cancellation before invoking the service and forward `appendLog` for progress events.

Logo uploads use a dedicated 5 MB memory-upload route. Replacement stores the new logo and updates the project pointer before best-effort cleanup of the old file; removal clears the pointer before cleanup. Studio previews and Remotion drafts retain the logo; only the existing preview BGM omission remains special-cased. VieNeu's selected Turbo backend accepts but does not apply the speed option, so mastering applies pitch-preserving FFmpeg `atempo` before loudness normalization. The final mastered WAV is probed and aligned; its measured duration is the value stored for scene timing.

## Word-timing groundwork (Task 34)

After storing each mastered WAV, video sends its bytes and original narration to the Python `/api/align` endpoint. Alignment is best-effort: a failure is logged and leaves the voiceover valid. The Python model is lazy-loaded from a pre-downloaded local path; see `lib/README.md` for the Python 3.12/CUDA setup. The TS request timeout is 120 seconds, covering cold model load and ordinary scene alignment.

The pure sequence alignment keeps narration whitespace tokens and maps normalized Whisper words in order. Insertions in the transcript are ignored; unmatched narration tokens receive spans interpolated between neighboring matched words (or the WAV boundaries). The named `MIN_WORD_ALIGNMENT_MATCH_RATIO` is 0.7: a result below that ratio is rejected to `null`. Negative, non-monotonic, and out-of-WAV spans are also rejected. Stored `wordTimings` carry the source `audioFileId`. Project-owned writes compare both that file ID and narration atomically, and audio replacement or narration replacement clears stale timings. The queued `align-word-timings` job backfills scenes sequentially, skips scenes without audio or with current timings, and checks cancellation between scenes. Rendering uses current timings for name/place popups.

## AI name and place popups (Task 82)

Analysis uses the project's selected AI model; legacy projects use that provider's registry default.

The video module analyzes eligible project scenes in one JSON-mode request and validates each phrase against a contiguous run in the scene's narration and timed words. Up to two ranked candidates are persisted per scene through the project service with a captured narration/audio stale guard. The prompt orders by importance and breaks equal-importance ties by first appearance; it requires verbatim contiguous wording, includes meaningful proper-name prefixes, and rejects generic nouns unless part of a proper name. Both AI clients honor JSON mode when requested; DeepSeek analysis explicitly sends `temperature: 0` (the SDK HTTP body is covered by a fake-fetch serialization test). Only malformed JSON is retried once; schema or scene-number validation failures fail without a second AI call. A valid empty candidate list is persisted as a fresh empty record, clearing prior choices; provider/parse errors and responses whose candidates are all rejected leave existing data unchanged. Render-time selection rechecks the narration hash, audio ID, and timed-word match; stale or invalid records are ignored and rule-based extraction remains the fallback. On narration edits, the prior record is retained but stale while `audioFileId` and `wordTimings` are cleared; there is no popup until new aligned audio exists, then rules are used while the record remains stale. Re-analysis refreshes the record and restores AI selection (`có kết quả mới`). Per-scene voiceover regeneration also retains its prior record as stale. Records are cleared only for duplicate projects or a bulk scene reset that sets `audioFileId` to `null` (`chưa phân tích`). Completion of the project-wide `align-word-timings` job triggers best-effort analysis; per-scene voiceover regeneration does not, so users may request analysis manually.

Re-analysis can select differently in an ambiguous/tied scene. The accepted tie-break is first appearance for equal-importance names; on the 2026-10-07 Rạch Gầm smoke pair, renderer keyword arrays matched across all scenes. Two candidate records differed only in the category assigned to the same phrase `Xiêm` (scene 32: `place`/`group`; scene 38: `place`/`group`); neither category variant changed the selected popup or Remotion props. Because render-time input comes from persisted candidates, it remains stable between analyses. This is not a claim that future analyses always return identical candidate records.

## Project-wide popup analysis (Task 97)

`popup-window.ts` retains the center hold/fade timing and keeps center anchors fixed. Lower-thirds now require at least 1.0 seconds of visible time; only when the anchor would otherwise fail may their start move up to 0.5 seconds earlier, clamped at scene-relative time 0. This measured compromise rescued 13/18 insufficient-window drops in the pre-change high snapshot while leaving the five sub-second cases dropped.

The active popup authority is the validated per-scene `popupPlan`, not legacy `nameCandidates` or narration heuristics. The AI boundary in `ai/` loads the versioned `popup-analysis.md` preset, parses strict scene verdicts, validates every anchor/display/evidence relationship against narration and word timings, and records a plan only through the project module's guarded writer. A valid `needed: false` verdict is retained with its reason and produces no popup. A valid empty result is therefore different from a failed run, which leaves the previous plan untouched.

`popup-safety-net.ts` applies only the named minimal constraints after project-wide merge: pinned entries win conflicts, overlapping or closer-than-three-second entries are resolved by importance then time, each scene keeps at most two, and repeated person/place/event mentions after their first project mention are recorded as `đã hiện ở cảnh trước`. Every removed entry remains in the plan's dropped list with its reason. `keywords.ts` converts only fresh, validated kept plan entries into the existing Remotion keyword shape. Film-look detection independently reads timed narration years, so disabling all displayed popups cannot disable the automatic film look.

Digit tracing accepts whole digit runs, Vietnamese number phrases, and verified evidence quotes. A single Vietnamese number word such as `năm`, `một`, or `hai` is intentionally lenient because it may be a quantity or ordinary narration; the AI kind/anchor verdict remains authoritative and validation still rejects fabricated numeric values.

Part B runs the project-wide analysis as the cancellable `analyze-popups` job. `POST /api/project/:id/popup-analysis` accepts the API or Claude CLI backend, density, and an optional registry Claude model; CLI availability is checked before enqueue and the worker checks it again. Prompts are measured in UTF-8 bytes, include the exact generated Zod JSON schema plus a compact example, split into primary-scene chunks with one-scene context overlap, and the parser requires exactly the primary verdict set for every chunk. Malformed JSON and schema failures each retry once; the second prompt includes the Zod error, while duplicate-scene, missing-scene, and validation failures leave existing plans untouched. The queue sets `maxAttempts: 1` because these are deterministic response-contract failures. API analysis uses the project's provider/model, while CLI runs use the shared `claude-cli` audit folders, bounded output, and cooperative cancellation without changing project AI settings. The worker returns the service result so terminal job documents retain `rejectedByValidation` and the other summary counts. After word alignment, automatic analysis is API-only. Its deliberate guard skips when any eligible scene already has a fresh plan; consequently, re-voicing only one scene leaves that scene without popups until a manual run, and Part C surfaces the stale/unanalysed warning. The render route returns `POPUP_ANALYSIS_IN_PROGRESS` while this job can write scene plans.

Part C renders the stored plan in `PopupAnalysisCard` inside Studio's Giao diện video area without changing the existing Scene → Audio → Video → Render DOM/tab order. The card exposes API/Claude CLI backend selection, low/medium/high density, provider/model status, fresh/stale/unanalysed messaging, progress/cancel state, and applied/expected/rejected counts. `PATCH /api/project/:id/scenes/:sceneId/popup-plan/flags` persists pin/suppress flags through the project-owned versioned writer. `PATCH /api/project/:id/scenes/:sceneId/popup-plan` validates an inline candidate with `validatePopupCandidate`, preserves its existing flags, reruns the project safety net, and returns `conflicts`; when a pin displaces another approved popup, the displaced row remains visible as `dropped` with reason `gần popup khác`. The card reads only `popupPlan`; legacy `nameCandidates` remains untouched and is not a selection source. Alignment now triggers only the new API popup auto-analysis; the old name-analysis worker call and Studio row/button are removed, while legacy routes/data remain available only for compatibility. Scene detail formats the first fresh kept person/place/event popup from the plan.

Part C's disposable Rạch Gầm verification is recorded under `data/files/.verification/task-97/`. `before.md` is the full pre-change selector inventory: 49 rows over 507.47 seconds (5.793/min); the legacy route-only 25-preview inventory is retained as `before-legacy-previews.md`. The final preset-v2 API low run applied 98/98 plans with 35 needed, 63 not needed, 29 kept, 17 persisted dropped rows, safety `droppedPopups: 16`, and `rejectedByValidation: 5` in 26.260s; one measured primary chunk made one provider call with no retry. The historical registry Claude Sonnet low run applied 98/98 with 10 needed, 88 not needed, 10 kept, 0 dropped, and `rejectedByValidation: 0` in 46.21s. A pre-change high snapshot measured 18 insufficient-window drops: lower-third minimum 1.0s would rescue 8/18, and conditional start up to 0.5s early raises this to 13/18 while preserving at least one second; the five remaining cases stay dropped. Preset v2 requires a number popup to display one figure plus its noun; final Remotion frames show `3.000 quân`, `19/1/1785`, and `kênh Bảo Định` at 1920×1080. The final API dump is `after-api-low-full.md`; historical CLI and first-pass tables remain in `after-cli-sonnet-full.md`, `after-api.md`, and `after-cli-haiku.md`. ## Large render files and long-video readiness (Task 104)

`renderFullProject` writes final and draft renders to an `outputPath` inside a temporary directory next to `FILES_DIR`, then stores the file with `storeFileFromPath`; FFmpeg and Remotion report size from `stat` and never buffer the final MP4. The temporary directory is removed after success or a pre-completion failure. If file metadata insertion fails, the file-store restores the source and the video service moves the finished render to `render-failed/` and logs the path; if that move also fails, the original temporary directory is retained and an error is logged. If project metadata linking fails after storage, the file ID and stored path are logged and the file remains available.

Remotion uses named `REMOTION_H264_CRF` 22 (override `REMOTION_CRF`, integer 0–51); FFmpeg scene encoding uses `FFMPEG_H264_CRF` 22 and `FFMPEG_H264_PRESET` `medium`. CRF controls quality, not a hard file-size limit; complex or noisy footage may still produce multi-gigabyte output. Draft renders use the same Remotion CRF at half scale.

Before rendering, the disk preflight estimates output at `RENDER_ESTIMATED_OUTPUT_BYTES_PER_SECOND` (3 MiB/s), adds 25% headroom and a 1 GiB reserve to each required path, counts referenced media plus normalized SFX for Remotion staging, budgets FFmpeg's normalized SFX and segment/concat copies, and adds a second output copy when the render temp path and `FILES_DIR` are on different devices (the `EXDEV` fallback). It checks free blocks with `statfs`, logs the estimate, and rejects insufficient space with a Vietnamese error. The output estimate alone is about 10.55 GiB for 3,600 seconds before headroom, reserve, media staging, and FFmpeg intermediates; actual encoded size varies with content.

Remotion stages assets with `copyFile` under the bundle's `public/renders/<renderId>/`, including image/video assets, keyframes, depth maps, voiceover, normalized SFX, BGM, and logo. The stage is removed after rendering. The renderer leaves concurrency at Remotion's default unless configured; depth scenes use concurrency 1. Full renders are served from `/files/<storedPath>` through `express.static`, which supports HTTP byte ranges for browser playback and downloads.

The job queue renews active worker leases every 60 seconds against a five-minute stale-recovery threshold, and job logs retain at most 1,000 entries of up to 8 KiB each. The disk check is a snapshot, not a reservation, so concurrent renders can overcommit a shared volume. Render cancellation remains cooperative only before and after `renderFullProject`; an in-flight FFmpeg/Remotion process is not interrupted by the current cancel flag. Worker shutdown waits for the current tick, but its SIGINT/SIGTERM handler force-exits after 10 seconds. Process loss can requeue a render from the beginning up to its configured `maxAttempts` (default 3); there is no render resume.

## Prerequisites and known gaps

- FFmpeg and ffprobe are external prerequisites selected by `FFMPEG_PATH`/`FFPROBE_PATH`, falling back to binaries on `PATH`.
- Remotion requires a compatible headless Chromium; the renderer may download it on first use. This is an external/first-run prerequisite and is not bundled or managed by this module.
- Real-binary integration tests are conditional on those executables being available; this acceptance run used FFmpeg/ffprobe and Remotion Chrome Headless Shell successfully. Pure builder/props/staging tests remain binary-free.
- Scene transitions, subtitles, partial rerenders, auto-ducking, and orphan-file cleanup are intentionally deferred.
- VieNeu/Freesound live-provider calls and browser Studio visual checks remain environment-dependent gaps; the Remotion Chromium prerequisite was launched successfully in this acceptance run and adapter tests continue to use mocks.

## Inactive scenes — Task 98 Part A

`contracts/scene-active.ts` defines active-scene filtering. Voiceover (including a requested start scene), word alignment, SFX, depth-map batches, duration recompute, name-keyword analysis, and popup analysis skip inactive scenes and report `skippedInactive`; all-inactive batches log a Vietnamese explanation and complete without entering an error loop. Batch logs/progress retain original scene numbers while progress denominators use active scenes. Popup analysis excludes inactive scenes from AI input, context overlap, and active-timeline start times, and does not replace their stored plans. Single-scene voiceover, SFX, preview, fit-to-clip, and popup-plan actions reject inactive scenes with `409 SCENE_INACTIVE`. `PATCH /api/project/:id/scenes/:sceneId/active` lives in this router and refuses changes while the exported scene-writing job-type list has an active job.

`renderFullProject` checks readiness against the full scene list first; the readiness helper ignores inactive scenes while retaining original indices for missing-asset errors. It then filters the scene list once before either renderer; this filtered list drives segment/timeline construction, audio concatenation and BGM duration, progress totals, and final duration. It passes original scene numbers separately for logs and atomically stores the exact ordered active IDs with the final render pointer. Draft renders do not change the final snapshot. Remotion scene previews receive the full active project as year/film-look context. `contracts/render-freshness.ts` compares the saved final-render snapshot with current ordered active IDs; legacy renders without a snapshot remain unmarked. Preview fingerprints also include active IDs through the target scene, so toggling an earlier scene invalidates that preview and later ones. SEO and video AI prompt builders, the audio-only listen queue, and Remotion year/film-look context all use active scenes. Chapter timestamps advance only over active-scene frames and warn when a chapter has no active scene.

Review-round HTTP regressions cover `409 SCENE_INACTIVE` for voiceover, SFX, preview, popup-plan flags, and popup-plan edits; the 12-job toggle guard checks that the full project remains unchanged. Mongo integration also confirms popup analysis leaves a stored inactive-scene plan unchanged. The preset loader accepts the checked-in CRLF `popup-analysis.md`; the earlier LF-only frontmatter regex rejected the captured `popup-analysis\r` value.
