# Module: seo

**Purpose:** Generate and store per-project YouTube packaging sections.
**Owns collection(s):** none; the project module owns the embedded `seo` package.
**May import (via their index.ts only):** project, channel.

**Public API:** prompt/parser helpers, generation service, SEO router configuration, and thumbnail replacement/removal services exported from `index.ts`.

## Invariants

- The project’s assigned channel is read through `channel/index.ts`; a missing channel is treated as unassigned. Description assembly is deterministic and combines intro, keywords, active-scene chapter timestamps, numbered HTTP(S) sources, assigned-channel links/footer/disclosure, and hashtags. Sources and keywords are the only blocks removed to meet the description length limit. Publishing guidance includes a neutral schedule reminder, optional same-channel comparison against other projects' chosen titles, and a Markdown schedule block when a valid long-video schedule and timestamp are available.
- Generated `descriptionKeywords` is stored with `descriptionIntro` when the description section is written. Hashtag defaults are merged only when tags are requested and a channel is assigned; footer, links, and AI disclosure are assembled in code and never sent in the AI prompt.
- Shorts candidates come only from active scenes, use per-scene frame rounding, and snap to scene boundaries. Valid chapter scene counts are required; 30–55 second runs are ranked by climax containment (or the longest active chapter when there is no active climax), then distance to the target center, with no overlap and at most three results. The picker is shared by server and client; `short-N` IDs remain stable while the first scene remains the same.
- Shorts content uses the separate `seo-shorts` preset and AI call. The AI returns exactly one content record per supplied window ID; the parser joins the deterministic ID, time range, and chapter number. A zero-window request stores `shorts: []` without a Shorts AI call. Manual mode accepts Shorts only as a standalone request; mixed Shorts/manual requests return 422. `generatedBy.promptVersion` records the main SEO prompt when main sections were called, otherwise the Shorts prompt version.
- SEO package reads default legacy `shorts` to `[]` and `longVideoUrl` to `''`. Every stored short has canonical hashtags with `#Shorts` and no more than five tags. `PATCH /seo` may edit text fields but rejects changed IDs, start/end times, or chapter numbers unless they match both the stored package and current deterministic windows. `{LONG_VIDEO_URL}` is substituted only for preview, copy, and Markdown export; an empty URL leaves the placeholder visible and warns in the checklist.

- AI output is validated before any project write; one validation retry is allowed.
- `generateSeoPackage` builds ordered `Phần chính` and eligible `Shorts` steps from the requested sections, reports equal progress slices from 5–95 and 100 after save, and logs Vietnamese request/response byte counts, elapsed time, retry, completion, cancellation, and failure events without prompts or generated text. A 30-second waiting heartbeat is capped at 20 per step across retries. The job repository retains at most 1,000 log entries and truncates each entry to 8 KiB.
- A generation request writes only the requested SEO sections and always records `generatedBy`.
- Thumbnail `imagePrompt` is a paste-ready generator prompt that already contains the overlay text; it is independent of the project's video visual style. The Studio/SEO UI copies it to Flow as is.
- Automatic API generation constructs the AI client from the project's selected `aiProvider` and `aiModel`; the shared model registry supplies a provider default for legacy projects. CLI generation is selected per request with `backend: 'cli'` and optional registry-validated `cliModel`; it never reads or writes the project's AI provider/model and stores `{ provider: 'claude', model, backend: 'cli' }` in `generatedBy`. API generation stores `backend: 'api'`; legacy provider-backed `generatedBy` records map to API, while manual records remain unchanged.
- `POST /api/project/:id/seo/generate` accepts optional `backend` (`api` by default) and `cliModel` in its strict body. CLI availability is checked before enqueue and in the worker; CLI jobs use one attempt so process, auth, and rate-limit errors are terminal instead of transient retries. The worker runs main SEO and Shorts calls sequentially through the shared Claude CLI chat wrapper. CLI prompts use the same formatter and JSON parsers, with a CLI-only JSON-only instruction and tolerant leading-text/fence extraction; manual import stays strict.
- The SEO toolbar keeps API/CLI choice and CLI model in local component state. It reuses the script CLI status query/API, hides project API provider/model controls while CLI is selected, and disables all generation actions with the reported status reason when CLI is unavailable.
- The preset source is `ai/presets/seo-documentary.md`; v8 adds description-keyword guidance and a `[[THUMBNAIL_TEMPLATE]]` sentinel. The default template remains in `## Thumbnail template`; a matching assigned channel can override only that block. The v7 template wording is preserved byte-for-byte in the regression fixture. Bump `version` in the frontmatter on any wording change.
- `POST /api/project/:id/seo/generate` enqueues `generate-seo` and returns an existing active job for the same project; the worker checks cancellation before invoking `generateSeoPackage`.
- Manual prompt/import and partial PATCH are synchronous; manual parse failures use `SEO_PARSE_ERROR` without replacing the pasted client text.
- `GET /api/project/:id/seo/channel-titles` asks the project public API for other projects' chosen title text only. The SEO client invalidates the result after a project channel assignment or chosen-title change; it never reads the projects collection directly. Schedule and AI-content checklist items are reminders, and suggested upload timing is explicitly unverified.
- SEO AI prompts use only active scenes for the opening excerpt and total duration. Chapter timestamps and generated descriptions advance over active-scene frames only; chapters with no active scenes are omitted and surfaced as a warning in the publish checklist.
- Thumbnail replacement stores a MIME-derived `.png`/`.jpg` file, points the project at it, then best-effort deletes the old file. Removal clears the project pointer before deleting the binary; project deletion also includes the thumbnail file in its app-level cleanup hook.

## Known gaps

- The reviewed SEO preset wording is not finalized yet, so automatic generation plumbing is implemented but content quality is not accepted as production-ready.
- Thumbnail metadata stores MIME/size but not pixel dimensions; the client displays the 1280×720 target and 2 MB limit, while a future pass can persist/validate dimensions for a stronger checklist.
