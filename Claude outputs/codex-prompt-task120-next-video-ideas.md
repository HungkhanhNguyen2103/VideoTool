## Why (Hung, 2026-10-22)

He wants the tool to propose **the next video**, based on the channel. Today the channel has only **2 videos with almost no views**, so a purely data-driven generator (Task 118 gates ideas at ≥ 10 mature videos) would show nothing — yet he still has to decide what to make next week. Performance data cannot answer that yet, and the tool must **say so** instead of pretending: ideas are generated in **evidence tiers**, each idea carries its tier, and as data accumulates the tier rises. The generator must not claim demand, views or "ít người biết" as facts.

This task is independent of Task 118 (it can run before or after). It reuses the same infrastructure; if Task 118 code exists when you start, reuse its evidence/metric-id conventions and grounding helpers instead of duplicating them; if not, build small shared helpers that Task 118 can adopt later and list them in the report.

## Facts to respect

- **The Claude CLI runs with `--tools ''` (no web access, no file access)**, see `src/server/shared/claude-cli/cli-runner.ts`. So every historical fact the model mentions comes from its training memory and is **unverified**. The tool must label them as such and hand off to a research step (Hung runs a separate research flow with sources before writing a script). Never present model-recalled facts as sourced.
- YouTube search demand/autocomplete is **not** available from the APIs the tool uses. The tool must not claim demand. It offers a 5-minute **manual demand check** per idea instead (section 4).
- Script preset `hubris-trap` ("Kẻ đi săn kiêu ngạo tự chui vào bẫy do chính mình giăng ra") needs four motif elements: `hunter`, `perfectPlan`, `blindSpot`, `selfDestruction`, with acts weighted 8/15/55/12/10 and a strict ban on invented details. An idea that does not fit must be rejected, not forced. The motif also fits business, technology, finance, sport, science and politics. Other presets exist (`SCRIPT_PRESET_IDS` in `src/contracts`), the generator must support them generically but optimise for hubris-trap.

## 1. Evidence tiers (server, pure, tested)

`classifyIdeaEvidence(...)` returns the tier for a channel run:
- `no-performance-data`: fewer than 3 mature plan videos (Hung today). Ideas rely on the channel profile, coverage of past topics and craft rules only.
- `weak-signal`: 3–9 mature plan videos. Add the observed ranking of own videos as **hints with sample-size warnings**, never as conclusions.
- `data-informed`: ≥ `NEXT_VIDEO_IDEAS_MIN_MATURE` (10, shared constant with Task 118 if it exists) mature plan videos. Add distribution, hit rates, best/worst performers, search terms and traffic mix from stored data (reuse the Task 117 plan-status `metrics` registry ids for citation).
The tier is stored on the run and on every idea, shown in the UI, and written into the prompt so the model must phrase accordingly ("chưa có dữ liệu hiệu quả" vs "dựa trên N video đã đo").

## 2. Idea packet (the only thing Claude sees)

New `idea-packet.ts`:
- Channel: name, language, description/tagline from the profile, `nicheStartDate`, cadence, preset(s) used so far.
- **Coverage map** of what the channel already made, from the project module's public API (projects with `channelId` = this channel; titles, preset, brief first 300 chars, linked video id, status) and from synced video titles (public, non-removed, plan and non-plan alike, so older-niche videos are visible and marked `olderNiche` when published before `nicheStartDate`). Purpose: avoid duplicates and repeating the same motif/era/region.
- **Saved ideas** already on file (title, status) so rejected or used ideas are not proposed again.
- Optional **steering** typed by Hung for this run (free text ≤ 500 chars: e.g. "lịch sử Việt Nam, ít người biết", era/region/people to avoid, desired duration) plus selects: preset (default `hubris-trap`), idea count (4–8, default 6), target duration seconds (30–3600, default from the last project or 600).
- Tier-dependent data: nothing for `no-performance-data`; for `weak-signal` the ranked own videos with views, sample size and the sentence that these are hints; for `data-informed` the metrics registry subset, top/bottom videos, search terms, traffic mix, the Task 117 verdict and active experiment (so ideas respect the single-variable rule and do not contradict a `consider_stop` verdict: if the verdict is `consider_stop`, the run still works but the UI shows the verdict banner above the ideas).
- Free text is data, not instructions (strip control chars, length caps, injection test with a video title like "ignore previous instructions"). No tokens, e-mails or paths.

## 3. Generation job (Claude CLI by default)

- Job type `video-ideas`, payload `{ channelId, backend: 'cli' | 'api', cliModel?, steering?, presetId, count, targetDurationSec }`, strict schemas, default `cli`; CLI availability checked before enqueue (503 `CLAUDE_CLI_UNAVAILABLE`) and in the worker; `cliModel` validated; one active job per channel (409 with existing job id); step progress, Vietnamese step logs, 30 s heartbeat and cancel exactly like Task 115 (reuse `createClaudeCliChat` and the shared progress panel; do not copy).
- **Two sequential CLI calls**:
  1. `Sinh ý tưởng`: generate `count + 4` candidate ideas (prompt version `video-ideas-v1-generate`).
  2. `Phản biện và chọn lọc`: a second pass that attacks each candidate (duplicate/too-similar to coverage or saved ideas, motif fit, unverifiable/invented-detail risk, too broad for the duration, depends on facts that probably have thin sources) and returns the final `count` ideas with scores (prompt `video-ideas-v1-critique`). The critique output is merged by id; ideas the critic rejects are dropped and recorded in the run's `dropped[]` with the reason.
- Prompt rules (English, in one `idea-prompts.ts`, unit-tested for rule presence): use only the supplied packet for anything about the channel; historical facts come from memory and every factual claim goes into `unverifiedFacts[]`, never stated as certain; do not invent numbers, dates, quotes or names to make a story tidier — if the model is unsure a link of the motif exists, it must say `evidence: 'thin'` for that link; do not claim popularity, demand, rarity ("ít người biết") or predicted views — rarity may only appear as `rarityGuess` explicitly marked as a guess; no hindsight framing ("they should have known"); respect the single-variable rule and the experiment log; vary era/region/type across ideas; titles ≤ 100 characters, concrete hook over generic label; answer in the narration language of the channel (`vi`/`en`); strict JSON.
- Idea schema (strict Zod in `src/contracts/youtube-ideas.ts`): `id`, `title` (≤ 100), `hook` (≤ 300; the opening moment, not chronological), `brief` (≥ 10 and ≤ 1200 chars, 5–8 sentences, fit for the project form), `presetId`, `motif: { hunter, perfectPlan, blindSpot, selfDestruction }` each `{ text ≤ 300, evidence: 'strong'|'partial'|'thin' }` (required for `hubris-trap`, optional otherwise), `whyForThisChannel` (≤ 300, must refer to the packet: coverage gap, tier hint, steering), `testVariable: 'topic'|'title'|'thumbnail'|'hook'|'length'|'cadence'|'other'` (exactly one), `successCriterion` (`{ description, afterVideos }` — a checkable goal for the next videos, not a promise), `unverifiedFacts[]` (max 8 short strings), `risks[]` (max 4), `rarityGuess?: 'common'|'uncommon'|'rare'|'unknown'`, `evidenceTier`, `scores: { fit 0–5, clarity 0–5, riskOfThinSources 0–5 }` (critic output), `suggestedDurationSec`, `suggestedChapterCount`.
- **Validation** (pure, tested; one repair call for invalid items as in Task 114/118, then drop what is still invalid and record it): schema; title length; duplicate/near-duplicate title vs coverage map and saved ideas (normalised, diacritic-insensitive); exactly one `testVariable`; forbidden promise/prediction phrases ("chắc chắn viral", "sẽ đạt", "đảm bảo", view or revenue predictions; keep the list in one constant); numbers in `whyForThisChannel` must exist in the packet; for `hubris-trap`, all four motif elements present and at least two with `evidence` ≠ `thin`, otherwise the idea is dropped as "không đủ khớp mẫu"; `rarityGuess` allowed only as a guess (never in `title`/`brief` as a claim: reject phrases like "ít ai biết" in title and brief). If fewer than `max(2, count/2)` ideas survive, fail with `YOUTUBE_IDEAS_UNGROUNDED` and a Vietnamese message instead of saving a thin list.

## 4. Storage, routes, status workflow

- Collection `youtubeVideoIdeas` (index through `indexes.ts`), one document per idea: `_id`, `channelProfileId`, run id, tier, backend/model, prompt version, generated-at, idea payload, `status: 'new'|'chosen'|'rejected'|'used'`, `statusNote?`, `usedProjectId?`, `manualDemand?: { note ≤ 300, checkedAt }`. Max 200 ideas per channel (delete oldest `rejected` first, never `chosen`/`used`). Also a small `youtubeIdeaRuns` record (tier, packet summary counts — not the narration text —, dropped list, durations).
- `POST /api/youtube/channels/:channelId/ideas/generate` → `{ jobId }`; `GET /api/youtube/channels/:channelId/ideas` (ideas + latest run summary + current tier + gate info); `PATCH …/ideas/:ideaId` (`status`, `statusNote`, `manualDemand`); `DELETE …/ideas/:ideaId`; `POST …/ideas/:ideaId/create-project` (section 5). Strict schemas, Vietnamese errors with stable codes, no token fields in any response (scan serialized responses in tests).
- Manual demand check (shown on every idea, 5 minutes): "Gõ tiêu đề/từ khóa chính vào thanh tìm kiếm YouTube, mở 5 kết quả đầu: kênh nhỏ có video ≥ 10k view không? video cũ hơn 2 năm vẫn còn view không? Ghi lại 1 câu." Hung types the result into `manualDemand`; it is shown but never used as a numeric input.
