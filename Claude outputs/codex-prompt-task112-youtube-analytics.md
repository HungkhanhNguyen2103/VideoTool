## Hard rules

1. **Read-only scopes only**: `https://www.googleapis.com/auth/youtube.readonly` and `https://www.googleapis.com/auth/yt-analytics.readonly`. No write scope anywhere, no upload code, no `videos.insert/update/delete`, no `playlists.*` writes, no comment writes. Add a unit test that asserts the requested scope list equals exactly these two.
2. **Tokens never leave the server and never reach logs, errors, job logs, API responses, the client, git or the project export.** Store refresh tokens encrypted at rest (AES-256-GCM, key from a new env `YOUTUBE_TOKEN_ENCRYPTION_KEY`, 32 bytes base64; refuse to start the connect flow if it is missing, with a Vietnamese message telling the user how to generate one — give the exact one-line Node command in the message and in `.env.example`). Access tokens are kept in memory only. The Google client secret comes from env `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET`; add them to `src/server/config.ts` with empty defaults and to `.env.example` (never touch `.env` itself). Redact `access_token`, `refresh_token`, `id_token`, `code`, `client_secret` in any logged error (add a small redaction helper with tests).
3. **OAuth is for a local desktop-style app**: authorization code flow with PKCE and a `state` parameter, redirect URI `http://localhost:<PORT>/api/youtube/oauth/callback` (use the configured `PORT`; also allow `http://127.0.0.1` as the same route). `state` is random, single-use, bound to the channel profile id, expires in 10 minutes; reject missing/mismatched/expired state. Request `access_type=offline` and `prompt=consent` so a refresh token is issued. The callback page shows a short Vietnamese success/failure message and closes or links back to the app. No third-party OAuth library is required; if you use `googleapis`, justify it in the report (bundle weight, maintenance) — the plain REST endpoints with `fetch` are acceptable and preferred for the three or four calls needed.
4. **One Google account may own several channels (brand accounts)**: after authorization list the channels of the authenticated account (`channels.list?mine=true`) and let the user choose which channel binds to the profile when there is more than one. Store `youtubeChannelId`, title, handle (`customUrl`), thumbnail URL, connected-at, and last sync. A YouTube channel can be bound to only one profile (409 with Vietnamese message). Disconnecting revokes the token at Google (`https://oauth2.googleapis.com/revoke`, failure is logged but does not block) and deletes the stored credentials and — after an explicit confirmation flag — optionally the synced data.
5. **Quota discipline**: Data API default quota is 10,000 units/day. List calls cost 1 unit; do not call `search.list` (100 units) at all — use the channel's `uploads` playlist (`playlistItems.list`) then `videos.list` in batches of 50. Track units used per day per Google project in a small `youtubeQuota` document (best-effort estimate, labelled "ước tính") and refuse a manual sync with a clear message when the estimate exceeds 8,000 units/day. Sync is manual (button) plus an optional once-per-day background refresh only while the server is running; no cron service, no new daemon. Use `ETag`/incremental logic where it is simple; do not over-engineer.
6. **Do not fabricate numbers.** Every metric shown must come from a stored API response; if the API did not return a metric (not available for the channel, too new, or the scope is missing), show "Chưa có dữ liệu" and say why in a tooltip. Verify the exact metric names, dimension combinations and availability (for example `impressions`, `impressionsClickThroughRate`, `averageViewPercentage`, `audienceWatchRatio` by `elapsedVideoTimeRatio`, `subscribersGained`, traffic sources, `estimatedRevenue` needing the monetary scope which we do NOT request) in the **official, current YouTube Analytics API documentation** before using them, list in the report what you verified and what turned out not to be available, and degrade gracefully. Do not rely on memory of the API.
7. **Data minimisation**: store only channel/video statistics and metadata for the user's own channels. No viewer-level or demographic data in this task. No data from other people's channels.
8. Do not change the render pipeline, the Blender work, the SEO generation prompts' output shape, or the Flow/Runner export JSON.

## 1. Contracts (`src/contracts/youtube.ts`, tests beside it)

- `YoutubeConnectionSummary` (what the client may see): `{ connected, youtubeChannelId, title, handle?, thumbnailUrl?, connectedAt, lastSyncAt?, lastSyncError? }`. No token fields exist in any client-facing schema.
- `YoutubeVideoStats`: `{ videoId, title, publishedAt, durationSec, isShort?, privacy, viewCount, likeCount, commentCount, fetchedAt }` (counts nullable when hidden), plus analytics fields per window when available: `{ views, estimatedMinutesWatched, averageViewDurationSec, averageViewPercentage, subscribersGained, subscribersLost, impressions?, impressionsClickThroughRate? }`.
- `YoutubeRetentionCurve`: array of `{ ratio, watchRatio }` (100 points as returned by the API) for one video.
- `YoutubeChannelDaily`: `{ date, views, estimatedMinutesWatched, subscribersGained, subscribersLost }` for the last 90 days minimum.
- `ChannelHealth`: computed values for monetisation progress (see section 4).
- Add optional `youtube` (connection summary) to the channel API output without breaking existing channel contract tests; legacy channels without it keep working.

## 2. Server modules

New module `src/server/modules/youtube` (public API through `index.ts`, `MODULE.md`, `docs.ts` like sibling modules; register routes in `app.ts`, indexes in `ensure-indexes.ts`):

- `oauth.ts`: PKCE/state helpers, authorization URL builder, code exchange, refresh, revoke. All HTTP through an injectable `fetch` so tests use fakes. Handle `invalid_grant` (revoked or **expired refresh token when the Google app is in "Testing" status, which expires tokens after 7 days**) by marking the connection `needsReconnect` and surfacing the Vietnamese message "Cần kết nối lại kênh (token hết hạn). Nếu app Google đang ở chế độ Testing, token chỉ sống 7 ngày."
- `credentials-store.ts`: encrypted token persistence (`youtubeCredentials` collection, unique on `channelProfileId`), encryption/decryption with the env key, key-rotation not required. Tests: round-trip, wrong key fails safely, nothing plaintext in the stored document, redaction helper.
- `sync.ts`: for one connected profile: channel info → uploads playlist → all video ids (paginate) → `videos.list` batches (snippet, contentDetails, statistics, status) → upsert into `youtubeVideos` (unique on `{channelProfileId, videoId}`), mark videos missing from the latest pass as `removed` rather than deleting. Detect Shorts by duration ≤ 3 minutes AND vertical aspect when available, else by duration only; store `isShort` with the rule used documented in `MODULE.md`. Then Analytics pulls: channel daily series (last 90 days), per-video totals for the last 28 days and lifetime, and per-video retention curve for the top N (default 15) most recent long videos and for any video the user opens in the UI (on-demand, cached 24 h). All Analytics requests are isolated so one failing metric group (403/400 "not available") does not fail the whole sync; record per-group status in `lastSyncReport`.
- `link.ts`: link a Video Tool project to a synced YouTube video: `PUT /api/project/:id/youtube-video { videoId }` (video must belong to the project's channel profile; one video per project; clear with `DELETE`). Suggest matches automatically by normalised title equality/containment against the project's chosen SEO title (reuse the normalisation from `seo-duplicates.ts` through the seo module's public API, do not import its internals) and by publish-date proximity; suggestions are only proposals, the user confirms. Store `youtubeVideoId` on the project through the project module's public API (add a field to the project contract with a legacy-safe default, mapper test for old documents).
- Routes (all under `/api/youtube`, standard `AppError` codes and Vietnamese messages): `POST /connect/:channelId` (returns the authorization URL), `GET /oauth/callback`, `GET /connection/:channelId`, `POST /disconnect/:channelId`, `POST /sync/:channelId` (runs as a job through the existing job module so it survives navigation and shows progress/log; one running sync per channel), `GET /channels/:channelId/overview`, `GET /channels/:channelId/videos?sort=&window=`, `GET /videos/:channelId/:videoId` (stats + retention), `GET /channels/:channelId/suggested-links`.
- Missing Google env or encryption key → every route that needs them returns a clear 503-style `AppError` with the setup instruction; the rest of the app is unaffected and the channel dialog shows the setup state instead of a broken button.
- Tests (fake `fetch`, temp DB like sibling modules): OAuth URL contains PKCE + exact two scopes; state single-use/expiry/mismatch; code exchange stores encrypted token only; refresh on expiry; `invalid_grant` → needsReconnect; channel choice among several; duplicate binding 409; sync pagination over >50 videos and >1 page; partial Analytics failure keeps video data; quota estimate refusal; removed videos marked; disconnect revokes and wipes credentials; no token string appears in any response or log line (assert by scanning captured logs for the fake token values).

## 3. Analytics service (pure, no I/O, `src/contracts/youtube-analytics.ts` or in the module's `analysis.ts` with contracts for shared parts; tests beside it)

All computations are deterministic functions of stored data:

- **Monetisation progress** (Hung's channels are new): from stored data compute subscribers (channel statistics), public long-form watch hours over the last 365 days, public Shorts views over the last 90 days, uploads in the last 90 days, and show progress against the two Partner Program tiers. **Put the thresholds in one named constants table with a "checked on <date>, verify at support.google.com/youtube/answer/72851" comment, and label them "mốc tham khảo, kiểm tra lại trên YouTube Studio"**; the official Studio value always wins. Do not compute or show revenue.
- **Per-video diagnosis**: rank videos by views per day since publish (age-normalised), by `averageViewPercentage`, by subscribers gained per 1,000 views, and by CTR if available; flag "early drop-off" when the retention curve loses more than X% of viewers in the first 30 seconds (named constant) and report the timestamp of the steepest drop segments (top 3) using the video duration. Compare each video with the median of the same channel (not across channels).
- **Cohort comparison by what Hung controls**: group videos by (a) duration bucket (<8 min, 8–12, 12–20, >20), (b) title features (length, contains number, contains question, contains parentheses/brackets — simple deterministic regexes, Vietnamese-aware), (c) publish weekday/hour bucket in the channel's timezone (from the profile schedule if set, else UTC+7), (d) the Video Tool script preset of the linked project (`documentary`, `explainer`, `hubris-trap`, `strategist`) and visual style, when linked. Each cohort shows n, median views/day, median avg view %, and an explicit **"mẫu nhỏ — chưa kết luận"** badge when n < 5 (named constant). Never present a difference as causal.
- **Channel trend**: 28-day vs previous 28-day change for views, watch time, subscribers, with the same small-sample/noise caveat for tiny channels (e.g. < 100 views in a window → "quá ít dữ liệu").
- Tests for every function with hand-built fixtures: ranking, age normalisation (video published today), drop-off segments, cohort bucketing edge cases (n=0, n<5), Vietnamese title regexes, trend with zero baseline (no division by zero → null), monetisation progress at 0 and above threshold.
