`docs/prototypes/studio-phan-canh/` (index.html, styles.css, app.js) has just been rewritten to accurately mirror `src/client/features/asset/StudioPage.tsx`'s real feature set and copy — per our usual convention (`AGENTS.md`: prototypes are the source of truth for layout, VN copy, tokens, behaviour). Now the direction runs the other way: the **live app's CSS has drifted from what the prototype specifies**, and I need it brought back in line.

Concrete example I can see from a live screenshot of the running app, scene card #01: `VISUAL PROMPT` (left) and `SFX PROMPT` (right) correctly sit side by side as two columns, but the media-preview box ("No asset yet") renders as a full-width block spanning underneath *both* columns, instead of stacking directly under the SFX/audio controls inside the right-hand column. The prototype's intended structure is 2 columns: left = visual-prompt block (full card height), right = SFX prompt + audio players + media-preview stacked vertically together. `StudioPage.module.css`'s `.body` is a 2-column CSS grid with 3 direct children (`.prompt`, `.audioControls`, `.preview`) relying on auto-placement to make the 2nd/3rd children share the right column — that's fragile and is very likely why it's currently misbehaving. Please don't guess at a patch from this description alone — open the real rendered page yourself (or reason from the actual CSS/DOM) and confirm the actual cause before fixing it; the fix should probably be an explicit wrapper (group `.audioControls` + `.preview` under one grid item, similar to how the prototype wraps them in `.scene-card__side`) rather than relying on implicit grid auto-placement.
