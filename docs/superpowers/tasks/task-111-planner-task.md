## Planner decisions

1. **Deterministic windows — `pickShortsWindows(project)`** pure, in a new `src/contracts/seo-shorts.ts`, input `Pick<ProjectDetail,'chapters'|'scenes'|'renderSettings'>`, output `{ windows: ShortsWindow[]; warnings: string[] }` with `ShortsWindow = { id, startSec, endSec, chapterNo, sceneIds: string[], sceneStartIndex, sceneEndIndex }`. The server and the client both call it; the AI never sees or chooses timecodes.
   - Timeline = ACTIVE scenes only, in order, with the same per-scene frame rounding as `chapterTimestamps` (use `secondsToFrames`, fps from `renderSettings`); `startSec`/`endSec` are frame-based seconds so they equal the YouTube chapter timestamps' timeline.
   - Chapter membership uses `chapter.scenesCount` slices exactly as `chapterTimestamps` does; if the counts do not match the scene list, return `windows: []` plus a Vietnamese warning (do not guess).
   - Candidate = a contiguous run of active scenes starting at a scene boundary; for each start index extend to the LONGEST run whose duration is ≤ 55 s; keep it only if ≥ 30 s (named constants `SHORTS_MIN_SEC=30`, `SHORTS_MAX_SEC=55`, `SHORTS_MAX_COUNT=3`). A single scene longer than 55 s makes no window.
   - Target span: chapters with `role === 'climax'` (first to last such chapter, active-scene span); if none, the single chapter with the greatest active duration (tie: earlier). `chapterNo` of a window = chapter of its first scene.
   - Rank: tier 1 = window entirely inside the target span, tier 2 otherwise; then smallest |window centre − target-span centre|; then earliest start. Select greedily, no overlap (strict overlap in time), at most 3. Output in rank order. `id = 'short-' + firstSceneId` (stable across regenerations).
   - Documented in a comment + MODULE.md. No narration analysis (no counting numbers/names/questions) in the score.
   - Tests: inactive scenes ignored and timeline compacted, snapping to boundaries, 30/55 bounds (exactly 30 ok, 55 ok, 55.04 not), no overlap, ≤3, short video (<30 s active) → `[]`, no climax → longest chapter, climax preferred over a closer non-climax window (tier), counts mismatch → `[]` + warning, determinism (same input twice), legacy chapters with `role: null`.
2. **Package schema:** `shorts` array max 3: `{ id, startSec ≥0, endSec > startSec, chapterNo int, hookLine ≤ 200, title ≤ 100, caption ≤ 500, hashtags (max 5, canonical via `normalizeHashtags`, ALWAYS contains `#Shorts`, guaranteed by a pure `ensureShortsHashtag`), reason ≤ 300 }`, default `[]`; `longVideoUrl` default `''`, either empty or http/https URL (≤ 500). Add both to `SeoPackageObjectSchema`, `SeoPatchSchema`, `GeneratedSeoSections` (shorts only), project `applyGeneratedSeoSections`. `startSec`/`endSec`/`chapterNo`/`id` are NOT editable from the UI; PATCH accepts the whole array but the server (project/seo route) must reject a patch whose ids/time fields differ from the stored/recomputed windows with 422 (Vietnamese message). Legacy packages parse unchanged (`[]`, `''`).
3. **`SEO_SECTIONS` gains `'shorts'`.** Update every enumerator: routes (generate, manual-prompt, manual-import schemas), worker `generate-seo`, `buildSeoPrompt` section handling, parse/output schema, client section lists/toolbar, tests that list sections. The default "all sections" request now includes shorts; when `pickShortsWindows` returns no windows the shorts section writes `shorts: []` WITHOUT an AI call.
4. **AI part (separate call, own preset):** new preset `ai/presets/seo-shorts.md` (id `seo-shorts`, `version: 1`, `## System` and `## Instructions`), loaded by a generalized loader (do not duplicate the parsing code; keep the `seo-documentary` loader behaviour and tests intact). New `buildShortsPrompt(project, windows, channel?)` → `{ system, user, jsonSchema, promptVersion: 'seo-shorts-prompt-v1/seo-shorts@1' }`. User message lists, per window: `window_id`, `chapter title`, `duration`, and the window's narration excerpt (joined active-scene narration, capped at 1200 chars per window; NOT timecodes). AI output (snake_case, strict): `{ shorts: [{ window_id, hook_line, title, caption, hashtags, reason }] }`. The parser requires exactly one entry for each given window id (no extras, no duplicates, no missing) → otherwise one validation retry, then `SeoAiOutputError`/502 and nothing written; then it joins by `window_id` with the deterministic window data. Rules in the preset: first 2 seconds hook, same no-invention rules as the main preset (no figures, names, dates not in the excerpt), vertical-video caption style, caption may contain the literal `{LONG_VIDEO_URL}` placeholder for a pointer to the long video, ≤ 100 chars title, ≤ 5 hashtags including #Shorts. Channel context (name/handle/language/default hashtags) goes in the user message like the main prompt; apply `mergeChannelHashtags` then `ensureShortsHashtag`, cap 5.
   - `generateSeoPackage`: when `shorts` is requested, run the shorts call separately from the main-sections call (main call only if other sections are requested). `generatedBy.promptVersion` stays the main call's version when there is one, otherwise the shorts version; document it in MODULE.md.
   - Manual mode: `shorts` is supported only as a standalone section request (manual prompt returns the shorts prompt; import parses the shorts JSON). A request mixing `shorts` with other sections in manual mode → 422 Vietnamese message "Gói Shorts cần tạo riêng ở chế độ thủ công." Automatic mode handles mixes.
5. **Placeholder & export:** pure `substituteLongVideoUrl(text, url)` replaces every `{LONG_VIDEO_URL}` with the url when non-empty, otherwise leaves the placeholder literal. Used in Markdown export, in "copy caption", and in the preview. UI highlights an unresolved placeholder (e.g. `<mark>`), and the checklist warns about it.

## Rejection criteria

- AI is allowed to choose or modify timecodes/ids (strict schema must not accept them; patch validation as in decision 2).
- Windows computed from narration content, or from inactive scenes, or not snapped to scene boundaries, or with overlap/bounds violations.
- Legacy projects/SEO packages stop parsing; an enumerating test deleted instead of updated.
- Placeholder substituted into stored data (substitution is display/export-time only).
- `#Shorts` missing from any stored short, or more than 3 shorts / 5 hashtags.
- YouTube-behaviour claim enforced as a hard error (30–55 s is our window policy, not a platform rule: label as "gợi ý" in the UI).
